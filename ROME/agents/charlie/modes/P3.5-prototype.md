## Purpose

Produce a **low-fidelity, throwaway** UI artifact so the sponsor can approve
look-and-flow **before** full generation. The prototype is a validation artifact,
not the deliverable; P5 still generates the real code. An accepted prototype
becomes an input constraint on P5 (layout/flow).

## Fidelity tiers (pick per project; default T1)

| Tier | Artifact |
|------|----------|
| T0 | wireframe / screen-flow render |
| T1 | static HTML/image mockup, real layout & styling, non-interactive |
| T2 | clickable static prototype (navigable, no backend) |
| T3 | runnable UI skeleton in the target stack, mocked data |

## Procedure

1. Read the design (`ARTIFACTS/_design/`) and requirements for the screens in scope.
2. Anchor to the project's design system / component library (predicts the real build).
3. Produce the prototype at the chosen tier into `ARTIFACTS/_prototype/`.
4. Self-check against the **UX checklist** (§ below) and report it.

## UX checklist (the visual-approval gate, owned by Sarah + sponsor)

- Navigation complete (every screen reachable; flows make sense)
- State coverage: empty / loading / error / populated
- Responsive breakpoints considered
- Accessibility basics: contrast, focus order, labels
- Consistent with the design system

## Return contract

Return one structured result (status, summary, artifacts=[prototype files],
traceabilityDeltas linking screens→requirements, blockers, and a `ux` object with
the checklist findings). Returning IS your record. Sarah gates GATE-P3.5 on the
UX checklist; the guard enforces the verdict.
