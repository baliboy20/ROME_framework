## Purpose

Produce a **low-fidelity, throwaway** UI artifact so the sponsor can approve
look-and-flow **before** full generation. The prototype is a validation artifact,
not the deliverable; P5 still generates the real code. An accepted prototype
becomes an input constraint on P5 (layout/flow), creating the
`prototype → screen → code` traceability link.

## Fidelity tiers (pick per project; default T1)

| Tier | Artifact | Owner |
|------|----------|-------|
| T0 | wireframe / screen-flow render | Reena |
| T1 | static HTML/image mockup, real layout & styling, non-interactive | Reena |
| T2 | clickable static prototype (navigable pages, no backend) | Reena |
| T3 | runnable UI skeleton in the target stack, mocked data | Charlie |

## Procedure

1. Read the design (`ARTIFACTS/_design/`, incl. Clara's
   `design-assets/design-system.md` — a required P3 output for ui-app projects,
   ROME-AX-26) and the requirements for the screens in scope.
2. Where the sponsor supplied **wireframe sidecars (`WF-*`)**, render THOSE frames —
   the sidecar bindings are the layout contract, and the gate criterion becomes
   "matches WF-x", not taste.
3. Anchor styling to the design system / component library (predicts the real build).
4. Produce the prototype at the chosen tier into `ARTIFACTS/_prototype/`.
5. Self-check against the **UX checklist** below and report it.

## UX checklist (the visual-approval gate, owned by Sarah + sponsor)

- Navigation complete (every screen reachable; flows make sense)
- Matches sponsor wireframes where supplied (WF-* sidecars)
- State coverage: empty / loading / error / populated
- Responsive breakpoints considered
- Accessibility basics: contrast, focus order, labels
- Consistent with the design system

## Rules

- **Throwaway by design.** No backend, no real data wiring, no production code —
  a prototype that starts accreting logic has left its mandate.
- **On BLOCK, iterate the prototype**, cheaply, until the sponsor approves
  look-and-flow. That is the entire point of doing this before P5.
- Do not modify design artifacts (Clara's) or requirements — flag gaps as blockers.

## Return contract

Return one structured result (agent, role, phase, status, summary,
artifacts=[prototype files], traceabilityEdges linking screens→requirements
(`satisfiesHow: documents`), blockers, and a `ux` object with the checklist
findings). Returning IS your record. Sarah gates GATE-P3.5 on the UX checklist
**plus sponsor visual approval**; the guard enforces the verdict.
